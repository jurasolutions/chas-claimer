## 6. Defects

### D01 Critical: a waterfall reorder over-claims the insurer when a sent claim ranks below it

**Repro**

1. Take visit D04b. CHAS 713f7437 is paid at $620. Flexi ac27baa3 is paid with $400 claimed (short
   accepted). Meridian 4ab2fb9c is approved at $288 (v2). The fee is $1,308.
2. In Settings > Payer waterfall, press "Move Insurance up" so the order is chas, insurance, medisave.
   Press Save settings.

**Expected:** sent claims are fixed inputs (the header of `server/services/rebuild.ts`). Meridian stays
at $288, or the desk flags the conflict. Who pays shows Flexi at $400.

**Actual**

- Meridian 4ab2fb9c goes back to Ready at **$688.00** (v3, approval_cleared, claimed $288 → $688), and
  the page says "Nothing to fix on this claim."
- Who pays shows CHAS $620, Meridian $688, Flexi $0, patient $0. "Other claims" on the same page shows
  Flexi $400 Paid.
- The claims on the visit total $1,708 against a $1,308 fee. The insurer is over-claimed by $400, and an
  officer could approve and send it with no warning.
- Evidence: `qa03-b9-overclaim.png`.

**Cause**

- `src/domain/claims/build.ts` `runWaterfall` (around line 270) sorts the plans by today's `rankOf`.
  `takeFixed` (around line 346) takes each sent claim only on its own turn. Meridian, unsent and now
  ranked above MediSave, allocates the whole remainder first, and the fixed Flexi segment shrinks to 0.
  The check that the split adds up to the fee still passes.
- `fixedDiffers` (build.ts around lines 279 and 285) does flag MEDISAVE_FLEXI, but nothing in `server/`
  or `src/` reads it, so the conflict never surfaces.
- `rebuild.ts` (around line 114) builds `fixed` from SENT_STATUSES (`src/domain/claims/state.ts:65`).

**Fix suggestion:** take every fixed claim off the remainder before allocating any unsent plan, and
surface `fixedDiffers` as a blocking finding when a sent amount can't be honoured.

**Failing test (red step).** It is in the session scratchpad as `qa3/redtest/reorder-sent.test.ts`. To
land it, paste it into `src/domain/claims/build.test.ts` with these relative imports. It fails with
`AssertionError: expected +0 to be 40000` at the split assertion. A control test with the default order
passes (Meridian 28800, Flexi 40000).

```ts
import { describe, expect, it } from "vitest";
import { generateClinic } from "../../../mock/synthetic-clinic/generate";
import type { IsoDate } from "../dates";
import { add, cents } from "../money";
import { splitVisit } from "../source-visit";
import { buildVisitClaims } from "./build";

const TODAY = "2026-11-13" as IsoDate;
const clinic = generateClinic({ seed: 7, asOf: TODAY });
const d04b = () => splitVisit(clinic.visits.find((v) => v.visitKey === "SC-D04b")!).clinical;

describe("QA 03 D01: a waterfall reorder after MediSave was sent", () => {
  it("D04b: sent CHAS $620 and sent Flexi $400 stay as sent; Meridian, now above MediSave, claims only what they left", () => {
    const settings = { ...clinic.settings, waterfall: ["chas", "insurance", "medisave"] as typeof clinic.settings.waterfall };
    const out = buildVisitClaims({
      visit: d04b(),
      settings,
      codeMap: clinic.codeMap,
      history: { visits: [], claims: [] },
      fixed: [
        { payerId: "CHAS", scheme: "chas", claimedCents: cents(62000) },
        { payerId: "MEDISAVE_FLEXI", scheme: "medisave_flexi", claimedCents: cents(40000) },
      ],
      annotations: {},
      today: TODAY,

    const split = Object.fromEntries(out.split.map((s) => [s.payer, s.cents]));
    expect(split.MEDISAVE_FLEXI).toBe(40000);
    const meridian = out.claims.find((c) => c.payerId === "MERIDIAN")!;
    expect(add(cents(62000), cents(40000), meridian.claimedCents)).toBeLessThanOrEqual(130800);
    expect(meridian.claimedCents).toBe(28800);
```
